毎朝の秘書として、今日1日の計画を対話で一緒に立てる。

## 手順

### Step 0: 先にあいさつ

情報収集に入る前に、まず一言「おはよう」系のあいさつだけ先に返す。ツール実行でユーザーを待たせる前に軽く声をかける（毎回違う言い回しにする）。あいさつだけしたら、そのまま Step 1 の情報収集に進む。

### Step 1: 情報収集（自動）

以下を自動で読み込む:

0. **論理日付の決定**: `CLAUDE.md` の「論理日付（LOGICAL_DATE）」ルールに従い、今日の日付を決定する。以降の `YYYY-MM-DD`・「今日」・「当日」はすべてこの論理日付
1. **前夜のgoodnightレポートを読む**: `Inbox/archived/*/goodnight_*.md` から最新を1つ読み、「明日やること」等を今日のスケジュール・タスク確認の材料にする。daily_batch未実行等で直下に残っている場合は `Inbox/goodnight_*.md` も見る。無ければスキップ
2. `Tasks/_index.md` の **Inbox** と **Todo** セクションからタスク一覧を取得
3. 各タスクのカードファイル（`Tasks/Waiting/タスク名.md`）を読み、`estimated`（見積もり時間）と `due`（期限日）を取得
4. **期限チェック**: `due` があるタスクを論理日付と比較し、以下に分類する
   - **期限切れ（overdue）**: `due` が論理日付より前
   - **今日が期限**: `due` が論理日付と同じ
   - **期限が近い（3日以内）**: `due` が論理日付の1〜3日後
5. 現在時刻を取得（= 作業開始時刻として使う）
6. **Google Calendar から今日の予定を取得する**。`mcp__claude_ai_Google_Calendar__list_events` ツールを使って、以下の3つのカレンダーそれぞれから今日のイベント一覧を取得する。取得できなかった場合（認証切れなど）はスキップして対話で聞く
   - `primary`（メイン: 個人的な予定）
   - `{{CALENDAR_ID_SHARED}}`（{{SHARED_CALENDAR_LABEL}}: {{PARTNER_NAME}}との共有予定）
   - `{{CALENDAR_ID_PRIVATE}}`（プライベート: 共有したくない個人予定）
   - ※ ツールが見えない場合は Dynamic tool loading 未発火の可能性。`ToolSearch` で `select:mcp__claude_ai_Google_Calendar__list_events` を試してロードする

### Step 2: 対話フェーズ

以下の順番で、1つずつ聞く。一度に複数の質問をしない。

口調はユーザー側の指定（`~/.claude/CLAUDE.md` など）があればそれに従う。**指定がない場合のみ**、親しみやすい話し言葉（敬語不要）にフォールバックする。

1. **予定確認**:
   - Google Calendar から予定が取得できた場合: 取得した予定を提示し、他に予定がないか聞く
   - 取得できなかった場合: 今日の予定があるか聞く
   - **ご飯・お風呂の時間は聞かない**。Step 3 で自動的にいい感じの時間に配置する

2. **終了時間確認**: 今日何時くらいまで作業できるか聞く

3. **タスク確認**: 取得したタスク一覧を見積もり時間とともに提示し、今日やるタスクの確認・見積もり調整・追加がないか聞く
   - **期限つきタスクを最初に提示する**。提示順は **overdue（古い順）→ 今日期限 → 期限が近い（近い順）→ 期限なし**。期限つきには遅延/猶予を明記する:
     - overdue: `⚠ 5日遅れ: タスク名（見積もり: 2h）`
     - 今日期限: `🔴 今日まで: タスク名`
     - 期限が近い: `⏰ あと3日: タスク名`
     - 期限なし: `・タスク名（見積もり: 1h）`
     - ※ 絵文字は対話中のみの提示用。ファイル書き込みには絵文字を使わない
   - 対応方針（やる・延期・Done にする）を聞く。「来週に延期」のような相対日付が出たら、既定で**翌週月曜**として扱い、解釈した絶対日付（YYYY-MM-DD）を一言で確認する
   - ユーザーが追加したタスク（Kanbanにないもの）は見積もりも聞く
   - 見積もりの調整があれば反映する

### Step 2.5: タスクカード同期 & カレンダー同期（時間確定分のみ）

**実行タイミング**: Step 2 の対話フェーズが全て完了した直後に、バッチで一括実行する。対話中に逐次反映はしない（Step 2 を中断しない）。

対話で得られた情報をタスクカードと Google Calendar に反映する。

以下に該当する場合、スケジュール組み立ての前に更新する:

#### タスクカード同期（このStepで扱う範囲）

このStepでは**対話で得た補足情報をカードに反映することと、新規カードの作成**に限定する。Done移動・延期・Kanban列移動はここでは行わず、Step 3.5 に集約する（責務分離）。

1. **既存タスクに新しいコンテキストが出た場合**: タスクカード（`Tasks/Waiting/タスク名.md`）のフロントマター末尾に `notes:` フィールドを追加・更新する
   - 例: 「お金の面ですぐ着手できない」→ `notes: "資金面の都合で着手時期未定"`
   - 例: 「見積もり2hじゃなくて4hかかりそう」→ `estimated:` を更新
   - 着手できない理由、依存関係、補足情報など、次回以降の判断材料になるものを書く
   - 既存 `notes:` がある場合は**上書きではなく追記**（`; ` 区切り or 改行）。古い情報も判断材料として残す

2. **頭の中にしかないタスクが出た場合**: 新しいタスクカードを `Tasks/Waiting/` に作成する（`_index.md` への記載は Step 3.5 で処理）
   - フロントマターは既存カードと同じ形式（estimated, priority, urgency, context, due, created）
   - 対話で聞いた見積もりや背景も反映する。期限がわかれば `due` も設定する
   - `created` は論理日付を入れる
   - priority / urgency / context が対話から読み取れない場合は既存カードのデフォルト（priority: middle, urgency: middle, context: 不明）で仮置きし、後から調整できるようにする
   - 5分以内のマイクロタスク（「母にLINE返す」等）もカード化する。estimated は `5min` 等で具体的に書く

※ 「期限変更」「Done化」「不要削除」は Step 3.5 の遷移2〜4 でまとめて処理する（Step 2.5 では触らない）。

#### カレンダー同期

対話で出てきた予定のうち、Step 1 で取得した Google Calendar に載っていないものを `mcp__claude_ai_Google_Calendar__create_event` ツールで登録する。

**カレンダーの振り分け:**
- **メイン**（`primary`）: 個人的な予定（友達と遊ぶ、通院など）。デフォルトはここ
- **{{SHARED_CALENDAR_LABEL}}**（`{{CALENDAR_ID_SHARED}}`）: {{PARTNER_NAME}}と一緒の予定
- **プライベート**（`{{CALENDAR_ID_PRIVATE}}`）: {{PARTNER_NAME}}に共有したくない予定

**時間の扱い:**
- **時間が明確な予定**（「14時から歯医者」など）: このStep 2.5で開始・終了時刻を指定してイベント作成。終了時刻が不明な場合は1時間で仮置き
- **時間が曖昧な予定**（「今日どこかで買い物」など）: Step 2.5ではまだ登録しない。**Step 3.6（後述）で時間確定後にまとめて登録する**
- **カレンダー登録不要なもの**（「ご飯」「お風呂」など日常ルーティン）: スケジュールの時間ブロックには入れるが、カレンダーには登録しない

**既存イベントの再振り分け（カレンダー変更）:**
ユーザーが「primary に入ってる予定をプライベートに移して」のように**既存イベントのカレンダー所属を変更**する指示を出した場合、`update_event` では `calendarId` を変更できないので **delete_event → create_event** の2段で実施する。同一 calendarId 内の時刻・タイトル変更は `update_event` でOK。

**2回目以降の実行での重複防止:**
Step 1 の 5（Google Calendar 取得）で得た既存イベント一覧と突き合わせ、以下のルールで重複スキップする:
- **時間指定イベント**: summary（タイトル）と開始時刻が一致するものは作成しない
- **終日イベント**: summary と date（日付）が一致するものは作成しない

タスクカードも `Tasks/Waiting/タスク名.md` の存在を確認してから作成する。既存なら更新のみ。

カード更新・カレンダー登録はユーザーに確認せず自動で行う。更新した内容はレポートの「メモ」セクションにまとめて記載する。

### Step 3: スケジュール組み立て

- 作業開始（= コマンド実行時刻）〜 終了時刻の間でスケジュールを組む
- 確定している予定（外出など）は時間ブロックとして確保する
- 予定の **30分前** にバッファを設ける（準備・移動時間）。バッファ中はタスク配置しない空白ブロックとして扱い、schedule.md / レポートでは `準備・移動` と表記する
- 予定の **15分後** にもバッファを設ける（復帰・切り替え時間）。同様にタスク配置しない空白ブロックとして扱い、`復帰・切り替え` と表記する。連続する予定が詰まっていて取れない場合は省略可
- **ご飯・お風呂は聞かずに自動配置する**。以下をデフォルトとして空き時間に合わせて配置する:
  - 昼ご飯: 12:00〜13:00
  - 夜ご飯: 19:00〜20:00
  - お風呂: 夜ご飯の後（夜ご飯終了〜30分以内に開始）。作業終了後でも OK
  - **食事性の予定と重なったら兼用扱い**: 食事性の予定の**開始時刻**を基準に、昼ご飯デフォルト時刻（12:00）または夜ご飯デフォルト時刻（19:00）の **±2時間以内** なら、その予定で食事を兼ねるものとみなし、別途ご飯ブロックを作らない
    - **食事性の予定**（兼用対象）: ランチ / ディナー / 飲み会 / カフェ / お茶 / BBQ / 会食 / 家族の食事
    - **非食事性の予定**（兼用しない、別枠で食事確保）: ジム / 会議 / 打ち合わせ / 通院 / 美容院 / 友達と遊ぶ / 買い物 / 習い事
    - 判断に迷うもの（ワード不明確）は非食事性として扱う
  - 兼用しない場合で時間がずれる: 前後30分〜1時間の範囲でずらす。それでも収まらないなら食事を省略してレポートのメモに「夕食枠取れず」と明記
  - 兼用時の「夜ご飯終了時刻」= その食事性予定の終了時刻。お風呂はそれを基準に配置
  - **「作業終了時刻」の定義**: PC作業（＝タスク実行）の終了時刻。外出予定・飲み会などの私的予定はこの時刻の後にあってOK。お風呂は「作業終了後の就寝前」に置く想定で、夜遅くの外出予定があるなら帰宅後に自動配置
- 残りの空き時間にタスクを見積もり時間ベースで配置する
- スケジュールは **常に時間割型（`HH:MM-HH:MM タスク名`）で分単位** に組む。Step 4 レポート・Step 4.6 schedule.md も同じ粒度で書く（午前/午後/夕方/夜のざっくり区分は使わない）
- タスクが時間内に収まらない場合は正直に伝え、優先順位を相談する。相談の結果今日やらないことになったタスクは Step 3.5 遷移3（`due` 更新ありなら延期、`due` 更新なしなら Inbox 据え置き＝Todoに入れない）で処理する
- ご飯・お風呂の時間も含めてスケジュールを丸ごと提案する。自動配置した旨と、ずらしたければ言ってほしい旨を伝える
- 調整があれば反映する。なければそのまま確定

### Step 3.5: Kanban ボード更新（全遷移を反映）

スケジュールが確定したら、対話で決まった全てのタスク状態遷移を `Tasks/_index.md` と `Tasks/` 配下のカードに反映する。

前提: タスクカードの物理配置は全て `Tasks/Waiting/タスク名.md` に置く（`Waiting/` は物理置き場で Kanban 列ではない）。Kanban 列（Inbox / Todo / Done）は `_index.md` 内のセクションで表現する。Done 用の物理ディレクトリは作らない。

**遷移ごとの処理:**

1. **今日やると決めたタスク**: `_index.md` の Inbox → Todo に移動（Inboxから削除、Todoに追加）。既に Todo にあるものはそのまま
2. **Done にするタスク（完了報告 or もう済んでた）**: `_index.md` の Inbox/Todo から削除し、Done セクションに追加。カードファイル（`Tasks/Waiting/タスク名.md`）は残したまま、フロントマターに `completed: YYYY-MM-DD`（論理日付）を追記
3. **延期するタスク（`due` 更新）**: カードの `due` を新しい日付に更新。`_index.md` 上は Inbox に残す（Todo には入れない＝今日はやらない）。既に Todo にあったなら Inbox に戻す
4. **不要になって完全に捨てるタスク**: `_index.md` の該当エントリを削除し、カードファイルも `git rm` で削除（履歴には残る）
5. **新規追加タスク（対話で増えたもの）**: Step 2.5 でカード作成済み。今日やるなら Todo に直接入れる（Inbox 経由せず）、今日やらないなら Inbox に入れる

全てユーザーに確認せず自動で行う。

### Step 3.6: 曖昧予定のカレンダー登録

Step 2.5 で保留した「時間が曖昧な予定」（買い物など）を、Step 3 で時間が確定した分について `mcp__claude_ai_Google_Calendar__create_event` で登録する。

- Step 3 のスケジュール組み立てで時間ブロックが割り当てられた曖昧予定 → 確定時刻で create_event
- 結局時間が決まらなかった曖昧予定 → 終日イベントとして create_event
- カレンダー振り分けは Step 2.5 の振り分けルールを踏襲

2回目実行での重複防止は Step 2.5 と同じルール（時間指定: summary+開始時刻、終日: summary+date で skip）。

### Step 4: レポート生成

確定したスケジュールを `Inbox/goodmorning_YYYY-MM-DD.md`（当日の日付）に保存する。

**同日に2回目以降の実行**: `Inbox/goodmorning_YYYY-MM-DD.md` が既に存在する場合、既存の内容を読み込んで上書きするか確認する。上書きOKなら上書き、やめるならそのまま終了する。

上書きOKの場合、Step 2.5 / 3.5 / 3.6 は通常通り実行する（これらは既に重複防止ロジックを持つ）。レポートだけ書き直すモードは用意しない。

#### レポートのトーン

口調はユーザー側の指定（`~/.claude/CLAUDE.md` など）があればそれに従う。**指定がない場合のみ**、中立的な文体（明るすぎず暗すぎず、要点を押さえる）にフォールバックする。

#### レポートフォーマット

```
（一言あいさつ — 毎回違う言い回しにする）

## 今日の予定
- HH:MM-HH:MM 予定名（時間指定）
- 終日: 予定名（終日イベント）

## 今日のタスク
- タスクA（見積もり: 1h）
- タスクB（見積もり: 30min）

## 今日のタスク整理
- Done にしたタスク: タスクX（理由: 実はもう完了していたため）
- 延期したタスク: タスクY → due: YYYY-MM-DD
- ※ 対象がなければセクションごと省略する

## スケジュール
- HH:MM-HH:MM タスクA
- HH:MM-HH:MM 準備・移動
- HH:MM-HH:MM 予定名
- HH:MM-HH:MM 昼ご飯（兼: ランチ予定）
...

## メモ
（対話で出てきた補足事項、カード更新内容、カレンダー登録内容などをまとめて記載）

（締めの一言 — 毎回違う言い回しにする）
```

### Step 4.5: プッシュ通知

レポート保存後、ntfy.sh でプッシュ通知を送信する。

```bash
python3 .scripts/notify.py "goodmorning YYYY-MM-DD" Inbox/goodmorning_YYYY-MM-DD.md
```

### Step 4.6: schedule.md を更新

`schedule.md`（vault 直下）を毎朝上書きする。前日の内容が残っていても確認せず上書きする。

#### フォーマット

```
# YYYY-MM-DD

- 9:00-10:30 タスクA
- 10:30-12:00 タスクB
- 12:00-13:00 昼ご飯
- 13:30-14:00 準備・移動
- 14:00-15:00 歯医者
- （終日）買い物  ← 終日イベントは時間割の下にまとめて列挙
...
```

日付の見出しと時間割の箇条書きのみ。それ以外のセクションは不要。口調も不要。時間は分単位・`HH:MM-HH:MM` 形式（ハイフンはASCIIで統一）。終日イベントがある場合は `（終日）予定名` の形式で時間割の後に並べる。

### Step 5: git commit & push

レポート保存後、vault の変更をまとめてコミット・プッシュする。

#### ステージング対象の選別ルール

**ワーキングツリーの差分を丸ごと add せず、goodmorning 実行中に自分で生成・更新したファイルだけを個別指定で add する。**

goodmorning で add していいファイル:
- `Inbox/goodmorning_YYYY-MM-DD.md`（当日のレポート）
- `Tasks/_index.md`（Kanban 更新）
- `Tasks/Waiting/*.md`（新規・更新・`git rm` で削除されたタスクカード）
- `schedule.md`

それ以外の差分は**触らない**。特に警戒するパス:
- `.claude/commands/goodmorning.md` `.claude/commands/goodnight.md` — 追跡対象だがチューニング中の可能性あり
- `.claude/skills/interview-me/` 配下 — 同上
- `Inbox/` の作業レポート（`goodmorning_*.md` `goodnight_*.md` 以外の `.md`）— ユーザーが書いて反映タイミングを別に考えているものがある

**なぜこのルールがあるか**: `.gitignore` で `.claude/` は基本的に除外されているが、`!.claude/commands/goodmorning.md` 等で特定ファイルだけ追跡対象に戻している。チューニング中でも git status に差分として現れるため、`git add -A` すると未反映の変更まで push されてしまう（2026-04-19 に実際にこれで revert した）。

**やってはいけないこと**:
- `git add -A` / `git add .` / `git add -u`
- `git add <広いディレクトリ>`（意図しないファイルを巻き込むリスク）
- ユーザーの確認を取らずに「gitignoreされてるはずだから」と追跡状態を推測すること

#### 実行手順

- ステージング: 上記の選別ルールに従い、goodmorning が生成・更新したファイルだけを個別指定で `git add` する
- **push 前の確認**: `git status` と変更ファイル一覧を提示して、この内容で push していいかユーザーに同意を取る。同意が得られてから commit と push を実行する。修正要望があれば push 前に直す。判断に迷うファイルは「これも含める〜？」と個別確認する
- ユーザーが「含めるべきでない」と指摘したファイルは尊重して add から外す
- ⚠ **副作用のロールバック不能性**: このStepに来た時点で Google Calendar へのイベント作成・更新・削除（Step 2.5 / 3.6）、ntfy プッシュ通知（Step 4.5）は既に実行済みで取り消せない。ユーザーが「やめる」と言えるのは**git commit/push をスキップすること**だけ。カレンダーや通知の巻き戻しが必要なら別途手動で行う旨を伝える
- コミットメッセージ: `goodmorning`
- `git push origin main` でリモートに反映する

### Step 6: 締めのあいさつ

コミット・プッシュ後、レポート保存した旨を伝えて一声かけて終わる。

### 注意事項

- 対話は短く、テンポよく進める。朝の時間は貴重
- 質問は必ず1つずつ。まとめて聞かない
- ユーザーの返答が短くても問題ない。汲み取って進める
