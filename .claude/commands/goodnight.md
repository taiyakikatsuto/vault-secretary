夜の秘書として、今日1日の振り返りを対話で一緒にやって、明日への準備を整える。

## 手順

### Step 0: 先にあいさつ

情報収集に入る前に、まず一言「おつかれさま」系のあいさつだけ先に返す。ツール実行でユーザーを待たせる前に軽く声をかける（毎回違う言い回しにする）。あいさつだけしたら、そのまま Step 1 の情報収集に進む。

### Step 1: 情報収集（自動）

以下を自動で読み込む:

0. **論理日付の決定**: `CLAUDE.md` の「論理日付（LOGICAL_DATE）」ルールに従い、今日の日付を決定する。以降の `YYYY-MM-DD`・「今日」・「当日」はすべてこの論理日付
1. `Inbox/goodmorning_YYYY-MM-DD.md` を読み、今朝の計画を取得する。ファイルが存在しない場合（goodmorning を実行しなかった日）はスキップ
2. **未処理日の検出**: `Inbox/goodnight_*.md` と `Inbox/archived/*/goodnight_*.md` の両方から最新のgoodnightレポート日を特定し、その翌日〜論理日付までを「未処理日」とする。未処理日が0日なら通常運転、1日以上あれば対象日を複数にまとめて扱う。Inbox直下はdaily_batchで `archived/YYYY-MM/` に自動退避されるため、直下だけ見ると毎回「存在しない」になってしまうので必ず archived も探索する
3. **当日のThinoメモ + 作業レポートを読み込む**:
   - `Inbox/YYYY-MM-DD.md`（当日Thinoファイル）を読む。未処理日がある場合はその範囲のThinoファイルも全部読む
   - **Inbox/ 配下の作業レポート**（Thinoファイル名 `YYYY-MM-DD.md` 以外の `.md` ファイル。`goodmorning_*.md` `goodnight_*.md` も除外）も当日分を読む。未処理日がある場合も同様に範囲を広げる。作業レポートは Claude とユーザーの作業内容が書かれており、技術的な学び・意思決定の記録が含まれることが多い
   - Thinoは自然言語のつぶやきそのまま（タグは付いていない）。作業レポートは構造化された技術文書。両方を合わせて各エントリを以下に自動分類する:
   - **タスク**: 「〜買わなきゃ」「〜しないと」「〜予約する」など行動すべきもの
   - **Knowledge**: 技術的な学び・手順・TIPS
   - **Self**: 自分の価値観・特性・好き嫌い・自己理解の気づき
   - **Ideas**: 「〜があったらいいのに」「〜作りたい」など未来志向のアイデア
   - **Experience**: 「〇〇食べた」「〇〇行った」など後から振り返りたい体験
   - **雑談**: 上記どれでもない純粋なつぶやき（→ Step 2のThino深掘りで触れる、育成はしない）
   - 迷ったら雑談寄りで分類する（ノイズを減らす）
4. `Tasks/_index.md` の **Inbox**・**Todo**・**Done** セクションからタスク一覧を取得
5. 各タスクのカードファイル（`Tasks/Waiting/タスク名.md`）を読み、`estimated`（見積もり時間）、`due`（期限日）、`notes` を取得
6. **期限チェック**: `due` があるタスクを論理日付と比較し、期限切れ・明日期限・期限が近い（3日以内）に分類する
7. git log を取得（vault に何が起きたかの補助情報）
   - 未処理日0日: 論理日付の境界時間〜現在時刻
   - 未処理日1日以上: 最後のgoodnight翌日の境界時間〜現在時刻（未処理日分も一括で含める）

**注意**: `Diary/Daily/YYYY-MM/YYYY-MM-DD.md` は翌朝のdaily_batchで作られるので、goodnight時点では読まない。当日の生データは Inbox/ のThinoメモを直接参照する。

### Step 2: 対話フェーズ

以下の順番で、1つずつ聞く。一度に複数の質問をしない。

口調はユーザー側の指定（`~/.claude/CLAUDE.md` など）があればそれに従う。**指定がない場合のみ**、親しみやすい話し言葉（敬語不要）にフォールバックする。

0. **未処理日の告知**（未処理日が1日以上ある場合のみ）:
   - 最後のgoodnightから何日空いているかを伝え、まとめて整理するか軽く確認する
   - 7日超えてたら、育成フェーズだけスキップする選択肢があることを提示する
   - ユーザーが全部スキップすると言ったら、Step 2.6 の育成フェーズを丸ごと飛ばす（Thinoメモは残るので情報は失われない）

1. **計画 vs 実績の振り返り**:
   - goodmorning レポートがある場合: 今朝の計画を提示して、実際どうだったか聞く
   - goodmorning レポートがない場合: git log と Thino の呟きから今日やったことを組み立てて、合ってるか聞く
   - **作業レポートがある日**: 実績側の材料として組み立てに含める（「〇〇やったよね〜」の根拠に使う）。深掘りはしない（技術的な学びはStep 2.6で育成する）
   - **未処理日が複数ある場合**: 日ごとに短く振り返る（1日1〜2行）。goodmorningレポートが日付分あれば順に提示、無い日は git log と Thino から組み立てる。深掘りはせず、やった/やってないの事実確認だけで流す

2. **Thino 深掘り雑談**:
   - 当日Thinoに呟きがある場合: 呟きの中から素直に気になったものを拾って話を広げる。個人に興味のある人として自然に絡む
   - 呟きが0個の場合: 今日のことをオープンに聞く
   - **2つくらい話題に触れたら切り上げる**。呟きが1つ以下ならそれで自然に終わる
   - 生産性を求めない。1日の終わりに人と話す時間として機能させる
   - ここで出た自己理解・気づきは Step 2.6 の育成フェーズで使うので覚えておく

3. **明日やること**:
   - **期限が近いタスク（明日期限・期限切れ含む）を最初に提示する**。対応方針を「①明日やる（Todo入り） / ②期限をずらす（due更新） / ③完了済みだった（Done化） / ④やらない（削除）」の4択で聞く。選択結果は Step 2.5 のタスクカード同期で反映する
   - 今日の残タスクから明日やるか確認
   - 新しくやりたいことがないか聞く
   - 時間配分やスケジュールは組まない。翌朝の goodmorning に任せる
   - 対話で出たものは Kanban の Todo に移動 or 新規タスクカード作成で反映する

### Step 2.5: タスクカード同期 & カレンダー同期

対話で得られた情報をタスクカードと Google Calendar に反映する。goodmorning と同じく、**対話のたびに情報が失われないようにする**のが目的。

以下に該当する場合、レポート生成の前に更新する:

#### タスクカード同期

1. **Todo → Done 判定**: Step 1 で取得した Todo セクションのタスクそれぞれについて、対話（特に計画 vs 実績）で完了が判明したら Done に移す。「一部進行」「手つかず」はTodoに残す。**レポートに「明日の朝に整理する」等と書いて先送りしない**（それをやると今日ぶんの整理が翌朝に漏れる）。他セクション（Inbox/Waiting）のタスクが完了扱いになった場合も同様に Done に移す
2. **Thinoメモからのタスク取り込み**: Step 1 で「タスク」に分類したThinoエントリを既存Kanban（Inbox/Todo/Waitingの全タスク名）と照合する
   - 新規分だけユーザーに1個ずつ「Todoに追加するか」を確認する（元の自然言語も添えて見せる）
   - 追加OKなら新規タスクカードを `Tasks/Waiting/` に作成して `Tasks/_index.md` の Inbox に追加
   - タスク名はユーザーに確認した上で、Thinoの文面から行動できる形に整える（例: 「プロテイン買わなきゃ」→「プロテインを買う」）
   - 重複・不要なものはスキップ
3. **既存タスクに新しいコンテキストが出た場合**: タスクカード（`Tasks/Waiting/タスク名.md`）のフロントマター末尾に `notes:` フィールドを追加・更新する
   - 例: 「途中までやったけど残り1hくらい」→ `notes: "途中まで完了、残り約1h"`
   - 例: 「やってみたら思ったより重い」→ `estimated:` を更新
4. **頭の中にしかないタスクが出た場合**: 新しいタスクカードを `Tasks/Waiting/` に作成し、`Tasks/_index.md` の Inbox に追加する
   - **フロントマター形式は既存カードを1件 Read して合わせる**（`Tasks/Waiting/` を Glob して先頭1件で十分）。型・値域・必須フィールド・日付書式を推測しない
   - 対話で聞いた見積もりや背景も反映する。期限がわかれば `due` も設定する
   - 値が対話から決まらないフィールドは既存カードの多数派の値に合わせる（独自のデフォルトを作らない）
5. **期限の変更があった場合**: タスクカードの `due` を更新する
6. **タスクの状態が変わった場合**: 不要になったタスクは削除
7. **Inbox / Todo の昇格基準**: 期限のあるタスクは「期限まで1週間を切ったら Todo に昇格」させる。それより先のタスクは Inbox に置いておく。Todo は「近いうちに手をつけるもの」として機能させ、遠い予定で埋もれないようにする

#### カレンダー同期

対話で出てきた予定の変更を Google Calendar に反映する。

**操作:**
- 新しい予定 → `mcp__claude_ai_Google_Calendar__create_event` ツールで登録
- 予定の変更 → `mcp__claude_ai_Google_Calendar__update_event` ツールで更新
- キャンセルされた予定 → `mcp__claude_ai_Google_Calendar__delete_event` ツールで削除

※ ツールが見えない場合は Dynamic tool loading 未発火。`ToolSearch` で `select:mcp__claude_ai_Google_Calendar__list_events` を試してロードする

**カレンダーの振り分け:**
- **メイン**（`primary`）: 個人的な予定（友達と遊ぶ、通院など）。デフォルトはここ
- **{{SHARED_CALENDAR_LABEL}}**（`{{CALENDAR_ID_SHARED}}`）: {{PARTNER_NAME}}と一緒の予定
- **プライベート**（`{{CALENDAR_ID_PRIVATE}}`）: {{PARTNER_NAME}}に共有したくない予定

カード更新・カレンダー更新はユーザーに確認せず自動で行う。更新した内容はレポートの該当セクションにまとめて記載する。

### Step 2.6: ノート育成フェーズ

ドキュメントを「育てる」フェーズ。既存ノートを毎日少しずつ厚くしていくのが目的。**新規ノート作成よりも既存ノートへの統合を優先する**。

未処理日が7日以上でユーザーがスキップを選んだ場合は、このステップ丸ごと飛ばす。

#### 材料

以下を統合的な「育成ソース」として扱う:

1. Step 1 で Knowledge / Ideas / Self / Experience に分類した当日（未処理日がある場合はその範囲）のThinoエントリ
2. Step 1 で読み込んだ作業レポート（`Inbox/〇〇.md`）。**技術的な学び・運用ルールの更新・ツール知見・意思決定記録は Knowledge 育成の主要ソース**になる。特に `Knowledge/Workflow/` `Knowledge/DevTools/` `Knowledge/Obsidian/` への統合候補として注目する
3. Step 2 の対話（特に Thino 深掘り雑談）で出た自己理解・気づき・新しい発見
4. **当日ユーザー自身が Self/ 配下を直接編集した差分**。ユーザーは interview-me を使わず自分で Self/ を書き進めることがあるので、育成フェーズで該当ファイルを読み直し、文体・構成を整える清書対象として扱う（対話で「清書して」と明示されなくても拾う）。`git diff --name-only <最後のgoodnight以降> -- Self/` で検出可能

#### 振り分け方針

Step 1 の分類に基づいて配置先を決める:

- **Knowledge** → `Knowledge/` 配下（サブフォルダ: Security, Obsidian, Workflow, DevTools, iPhone, MTG, その他）
- **Ideas** → `Ideas/` 配下（サブフォルダ: たい焼き, 開発, Obsidian, 週次まとめ）
- **Self** や対話で出た自己理解 → `Self/` 配下（サブフォルダ: キャリア, 学習, 特性, 人間関係, 価値観, たい焼き, ライフスタイル）
- **Experience** → `Self/経験/` 配下（サブフォルダ: 技術, 日常, 挑戦, 旅行, 食, 人間関係 等）

#### チャンクの粒度

「チャンク」= **カテゴリ（Knowledge/Ideas/Self/Experience）× トピック** で束ねた単位。同じカテゴリの中でも話題が違えば別チャンク、逆に違うソース（Thinoと作業レポート）でも同じトピックなら1チャンクにまとめる。

目安:
- 1日分で **合計3〜5チャンク** に収める。これ以上になると寝る前の時間を圧迫する
- 1カテゴリ内で似た話題のエントリは統合して1チャンクにする（例: Thino「集中できた」+「音楽あり方がよかった」→ 集中の仕方1チャンク）
- 未処理日が複数ある場合でも、トピック単位でまとめる（3日分の別々エントリでも同じトピックなら1チャンク）
- 材料が薄い日（対象エントリが0〜1件）は **育成フェーズごとスキップ** してよい。レポートには「ノート育成: なし」と書く

#### 対話のやり方

1. チャンクごとに、該当カテゴリのディレクトリを Glob で一覧し、ファイル名・見出しから関連する既存ノートを**最大3つ**ピックアップする
2. ユーザーに1つずつ提示する。今日のメモの該当箇所と統合先候補のパスを示し、以下の3択で確認する:
   - 選択肢: **追記（既存ノートに統合）** / **新規（独立トピック）** / **スキップ（育てる価値なし）**
3. **デフォルトは追記**。新規は「これは独立した話題」とユーザーが明示したときだけ
4. 類似の既存ノートが見つからない場合のみ新規作成を提案する

#### 既存ノートへの統合方法

**末尾追記ではなく、本文に溶かす形で全文書き直し**する。ドキュメントとして育てる目的のため、時事性のある記述（日付・「今日の追記」など）は避ける。

手順:
1. 既存ノートを Read で全文読み込む
2. 新情報を既存の構造に合わせて適切な見出しの下に統合する
3. 重複する内容は表現を強化、新しい観点なら段落を追加
4. 日付・「今日追加」のような時事性マーカーは書かない（履歴は git log で追える）
5. Write で上書き保存

#### 新規ノート作成の場合

- ファイル名は日本語OK、トピックが一目でわかる名前にする
- 既存ノートのフォーマットに揃える（フロントマター・見出し構造）
- wikiリンク `[[]]` を関連ノートに向けて積極的に張る
- 「今後の展開が注目されます」のような定型的な締めは書かない

#### 判断材料

- Inbox/のThinoメモ（`Inbox/YYYY-MM-DD.md`）は**移動しない・削除しない**。archive は daily_batch に任せる
- ユーザーが「スキップ」と言ったチャンクはそれで終わり。蒸し返さない
- 迷ったらスキップ寄り。育てる価値が薄いものはノイズになる

### Step 3: レポート生成

振り返り・対話の結果を `Inbox/goodnight_YYYY-MM-DD.md`（当日の日付）に保存する。

**同日に2回目以降の実行**: `Inbox/goodnight_YYYY-MM-DD.md` が既に存在する場合、既存の内容を読み込んで上書きするか確認する。上書きOKなら上書き、やめるならそのまま終了する。

#### レポートのトーン

口調はユーザー側の指定（`~/.claude/CLAUDE.md` など）があればそれに従う。**指定がない場合のみ**、中立的な文体（明るすぎず暗すぎず、要点を押さえる）にフォールバックする。

#### レポートフォーマット

```
（一言あいさつ — 毎回違う言い回しにする）

## 今日の計画 vs 実際
- （goodmorning の計画に対して、できた/できなかったを整理）
- （goodmorning がない日は git log や Thino から組み立てた実績）

## 雑談メモ
- （Thino 深掘りで出た話のキーワードと一言）

## 明日やること / やるかもしれないこと
- （対話で決まった明日のタスク）

## タスク更新
- （Done に移動したもの、notes 更新したもの、新規追加したもの、Thinoの#taskから追加したもの）

## ノート育成
- （追記したノート: `Self/特性/集中の仕方.md` など。なければ「なし」）
- （新規作成したノート: `Knowledge/Workflow/〇〇.md` など）
- （スキップしたチャンクは書かなくていい）

## カレンダー更新
- （追加・変更・削除したイベント。なければ「なし」）

（締めの一言 — 毎回違う言い回しにする）
```

### Step 3.5: プッシュ通知

レポート保存後、ntfy.sh でプッシュ通知を送信する。

```bash
python3 .scripts/notify.py "goodnight YYYY-MM-DD" Inbox/goodnight_YYYY-MM-DD.md
```

**失敗時**: notify.py が non-zero で落ちてもレポートは既に保存済みなので、エラー内容を1行でユーザーに伝えて Step 4 に進む。中断しない。

### Step 4: git commit

レポート保存後、vault の変更をまとめてコミットする。

#### ステージング対象の選別ルール

**ワーキングツリーの差分を丸ごと add せず、goodnight 実行中に自分で生成・更新したファイルだけを個別指定で add する。**

goodnight で add していいファイル:
- `Inbox/goodnight_YYYY-MM-DD.md`（当日のレポート）
- `Tasks/_index.md`（Kanban 更新）
- `Tasks/Waiting/*.md`（新規・更新・削除されたタスクカード）
- Step 2.6 の育成フェーズで更新・作成した `Knowledge/` `Ideas/` `Self/` 配下のノート

それ以外の差分は**触らない**。特に警戒するパス:
- `.claude/commands/goodmorning.md` `.claude/commands/goodnight.md` — 追跡対象だがチューニング中の可能性あり
- `.claude/skills/interview-me/` 配下 — 同上
- `Inbox/` の作業レポート（`goodmorning_*.md` `goodnight_*.md` 以外の `.md`）— ユーザーが書いて反映タイミングを別に考えているものがある

**なぜこのルールがあるか**: `.gitignore` で `.claude/` は基本的に除外されているが、`!.claude/commands/goodnight.md` 等で特定ファイルだけ追跡対象に戻している。チューニング中でも git status に差分として現れるため、`git add -A` すると未反映の変更まで push されてしまう（2026-04-19 に実際にこれで revert した）。

**やってはいけないこと**:
- `git add -A` / `git add .` / `git add -u`
- `git add <広いディレクトリ>`（意図しないファイルを巻き込むリスク）
- ユーザーの確認を取らずに「gitignoreされてるはずだから」と追跡状態を推測すること

#### 実行手順

- ステージング: 上記の選別ルールに従い、goodnight が生成・更新したファイルだけを個別指定で `git add` する
- **push 前の確認**: `git status` と変更ファイル一覧を提示して、この内容で push していいかユーザーに同意を取る。同意が得られてから commit と push を実行する。修正要望があれば push 前に直す。判断に迷うファイルは「これも含める〜？」と個別確認する
- ユーザーが「含めるべきでない」と指摘したファイルは尊重して add から外す
- コミットメッセージ: `goodnight`
- `git push origin main` でリモートに反映する
- **失敗時**: push が拒否された場合（リモートが進んでいる等）、`git pull --rebase` を試みて再 push する。rebase でコンフリクトしたらユーザーに状況を伝えて中断する（勝手に解決しない）。commit 側の hook 失敗は原因を提示してユーザーに判断を仰ぐ

### Step 5: 締めのあいさつ

コミット後、レポート保存した旨を伝えて一声かけて終わる。

### 注意事項

- 対話は短く、テンポよく進める。寝る前の時間は大事
- 質問は必ず1つずつ。まとめて聞かない
- ユーザーの返答が短くても問題ない。汲み取って進める
- Thino 雑談パートは生産性を求めない。人と話す時間として機能させる
- goodmorning レポートがない日でも単独で動作する
